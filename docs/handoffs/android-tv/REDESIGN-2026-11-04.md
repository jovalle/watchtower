# Native TV Redesign Acceptance — November 4, 2026

Follow-up: [playback/control repair](REPAIR-2026-11-04.md) resolves the startup failure below and standardizes controls, branding and pointer input. This document records the earlier pass.

The approved TV redesign is implemented and installed on the Google TV API 36 emulator. Requests and Issues are now destinations in the expanding symbol rail. The app retains Watchtower's dark surfaces and mango focus treatment, with compact action symbols and readable labels on focus.

## What Changed

- Shared local Lucide symbol controls cover player transport/menus, detail actions, catalog tools, pairing actions, and settings actions. Accessible names and minimum 48dp targets remain; media titles and selection values retain text.
- Home uses a featured header and denser media rows. Libraries provide Library/Collections, sorting/filtering and denser grids. Show → season → episode pages retain their source and context; details provide More, overview, cast and related sections where supplied.
- Requests shows linked-user history, filters, pagination, status and title details. Issues shows reports, status, details and conversation, with remote scrolling for long text. Native reads recheck the active principal and reuse upstream per-user visibility.
- Fixed details More focus restoration and player overlay hardware Back handling. The latter now uses Android's BackHandler; intercepting key-down/up directly failed a real hardware-event regression.

## Playback Limitation

Fresh episode HLS starts intermittently returned upstream HTTP400 after an earlier successful decoded session. A temporary redacted fetch trace recorded eight 400s and one 200 with the same seven logged safe parameters; it did not capture every request parameter and does not establish a root cause or resolution. Subsequent playback on the final APK succeeded, including a resume at 1:56. No speculative backend workaround was added. Reliable repeated starts still need investigation.

Temporary tracing was removed from the running server. Physical TV hardware, HDMI audio passthrough, HDR hardware behavior, long-duration playback and release-build device execution were not checked in this pass. Request/report writes remain fixture-only.
