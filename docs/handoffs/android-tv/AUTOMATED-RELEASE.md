# Android TV Automated Releases

After the web CI workflow succeeds on `main`, the release workflow tests, lints and builds Android TV before running semantic-release. When a release is created, it builds a signed Android TV APK from the release tag, verifies its signing certificate, and attaches the APK and SHA-256 checksum to that GitHub release. Signing or upload failures fail the job; a release may exist without an APK if this job fails, so inspect its status and rerun the failed job after correcting the cause.

The signing job reads the four `WATCHTOWER_TV_*` values from the dedicated Watchtower Android TV Signing Infisical project's Production root. This project contains copies of the entries in the Watchtower project's Production `/android-tv` folder; keep both copies synchronized when changing them. Restrict the dedicated identity's GitHub OIDC trust to `jovalle/watchtower`, the `production` environment, the release workflow and the `main` branch. Set the non-secret GitHub Actions variable `INFISICAL_ANDROID_TV_IDENTITY_ID` to the identity ID in the `production` environment. Protect that environment and its deployment branch rules. The workflow requests no signing secrets on pull requests.

Release version codes are `major * 1,000,000 + minor * 1,000 + patch`; minor and patch must be below 1,000. The workflow checks the signed APK against the existing Watchtower TV certificate and requires a version code above 3. Future separately signed builds must use a smaller version code than the next release or Android will reject the update. Preserve the signing identity for upgrades; replacing it prevents in-place updates.

The APK requires Android API 28 or later. Download the APK and its checksum from the release, verify the checksum, and use `adb install -r watchtower-tv.apk` to update a device that already has an app signed by the same key. Do not uninstall the existing app to work around a signature mismatch: uninstalling removes its local data.
