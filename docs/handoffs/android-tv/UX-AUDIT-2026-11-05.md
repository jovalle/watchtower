# Android TV UX audit and hardening

The audit found functional gaps beneath the completed visual redesign. This pass fixes request eligibility, media identity/artwork, feedback, remote focus and recovery in the existing native client. It preserves the Netflix-led Watchtower design, Plex library depth, main's separate layout audit and Watch Together. Work remains uncommitted in `codex/android-tv`.

## Findings and resulting behavior

| Area | Cause and user impact | Result |
| --- | --- | --- |
| Requesting available movies | Neither the button, ViewModel nor native POST checked eligibility | Fresh backend preflight rejects available/blocked/active standard requests; the client also guards direct calls and disables unsafe actions during lookup/failure |
| Available external titles | Search deduplication was limited; request/issue inbox titles always entered external details | Availability resolves exact TMDB IDs through the active profile's scoped Plex client and offers Open in Library |
| TV/4K requests | A blanket availability rule would block legitimate missing seasons or confuse4K with standard availability | Partial TV can request missing seasons; standard requests use standard status, independently of4K |
| Duplicate/stale mutations | The mutation lock started inside a coroutine; a successful response published before checking its owner | Lock is immediate, stale identity results are discarded, and successful request responses remain non-requestable |
| Successful write followed by failed refresh | A request could be created but displayed as failed, inviting another submission | Creation returns a conservative pending/non-requestable success when its follow-up read fails |
| Service permissions and outages | Upstream mutation/profile errors could become generic internal500 failures | Sanitized permission, validation, conflict, quota and network errors retain their actual meaning; identity is rechecked after issue creation |
| Request/issue status feedback | All statuses inherited ordinary row text; counts called repeated issue records “Titles” | Labeled status badges use consistent success/pending/progress/attention/neutral colors on focused and unfocused rows; counts say Requests or Issues |
| Pending status meaning | Pending media does not necessarily mean an approval decision is outstanding | Awaiting Approval is shown only for a matching pending standard request; otherwise the status remains Pending |
| Watchlist covers | Native image URLs were wrapped twice; relative Discover artwork could be resolved against the wrong server | Sources retain local/Discover origin and receive exactly one protected image proxy URL |
| Playlist presentation | Supplied covers were unused; entries were text-only | Playlist mosaics, item covers, years, readable fallbacks and existing viewing/detail actions are visible |
| Playlist action alignment | Play labels repeated full titles and expanded each row's control width | Shared square Play/Details/Remove symbol actions keep columns aligned; Play retains the full title in its accessibility description |
| List item identity/navigation | External items were inert; movie/show IDs collided; local matches retained external badges | Typed keys are distinct, external details are connected, and local titles open locally without a false Not in Library badge |
| Lists loading and Back | Errors/partial failures/empty states were hidden; source and focus were not restored | Visible retry/recovery, selected source, saved focus, delayed-return restoration and a fallback when a title disappears |
| Playlist pagination/removal | Captured focus overwrote newer focus; deleting before an offset cursor skipped a title | Latest focus survives page responses; removal invalidates offset paging and reloads; busy removal is explicitly disabled while loaded Play/Details remain usable |
| Long playlist chooser | An unscrollable dialog could hide later choices/Cancel; first smart item could capture focus | Bounded scrolling panel focuses its first enabled playlist and reaches the last choice and Cancel by D-pad |
| Failed issue submission | Dialog closed before the POST, destroying the remote-entered draft | Dialog retains draft/type through pending/failure, announces the error and closes on successful issue completion |
| Profile/library/search recovery | Failed profiles trapped entry; failed libraries disappeared; unchanged failed queries could not retry | Focused Retry at the profile gate, visible library failure/retry, and retry of the same query while retaining filters |
| Settings integrity | Remote load failure left local defaults editable, overwriting unrelated saved values | Local preferences hydrate before network work; writes transform the latest persisted values; remote settings can retry in the same category |
| Initial player failure | Retry called a replacement path requiring a descriptor that initialization never installed | Retry restarts initialization when needed, guards duplicate attempts, receives focus, and keeps descriptor-dependent menus disabled |
| Optional edition lookup | A failed sibling-edition lookup blocked an otherwise valid media detail response and player startup | Edition discovery is optional; valid details remain playable during lookup outages, while authorization failures still propagate |
| Missing title versus outage | Required metadata reads converted every non-authorization Plex failure into Media Not Found | Actual404 remains not-found; network/5xx failures retain a retryable Plex Unavailable response with retry timing |
| Home freshness | Cached Home retained obsolete settings and playback progress | Return refresh preserves mounted content/focus, updates progress/preferences and offers recovery if refresh fails |
| Inbox/list metadata freshness | Returning to Requests/Issues or My Lists could retain old statuses/counts | Return refreshes their data; same-query inbox refresh/error preserves mounted rows, stable item IDs preserve focus, and changing page/filter clears prior-query rows |
| Plex progress transport | Shared reporting used GET while the current PMS API specifies POST | Timeline reporting uses POST for playing/paused/stopped, preserving actual milliseconds, playback identity and existing error behavior |
| Stop during upstream failure | Failed final progress reporting skipped the transcoder stop command | Valid stops attempt existing authorized cleanup in finally and retain progress errors; invalid bodies and ownership failures perform no upstream action |

## Coverage and verification

The audit traced source, callers, contracts and existing tests for pairing/profiles, rail navigation, Home, libraries/genres/search, movie/show/season/episode details, external titles, watchlists/playlists, Requests/Issues, settings and playback. Native TV remote behavior takes precedence over phone-specific navigation conventions.

Focused regression runs first reproduced request safety/race failures, offset paging/focus failures, thirteen device recovery/presentation failures, and a disappearing-title focus failure. Integrated verification also caught dialog focus ownership and loading semantics attached to a non-actionable wrapper; both were corrected and rechecked. Tests use synthetic data for all mutations and failure cases.

The return-freshness sweep reproduced four additional device failures and one query-clearing state failure before implementation. It verifies changed request/issue status after detail/Back, updated playlist counts after return, retained focus through refresh loading/error, stable focus when a row is inserted, and no prior-query rows after changing filter/page. Sidebar sources retain their established saved navigation stacks; Back returns from a restored title detail to its source inbox.

Final real playback also exercised an actual upstream startup failure. Retry recovered to102seconds after the preceding96second play-through and Stop completed204. Source tracing isolated the movie route's503 path to optional edition discovery. Regression tests reproduced optional503/404/network failures, retained successful edition filtering and verified401 propagation. Separate shared-helper tests reproduce misleading metadata404s and verify truthful retryable outage classification. These changes preserve the established playback mapping, buffer budget, principal checks and stop ordering.

Stop failure tests then reproduced skipped transcoder cleanup on both HTTP503 and network errors. Cleanup now runs in finally after request validation and ownership checks, using the existing principal recheck and replaced-session guard. Tests verify that reporting errors remain visible and malformed stops issue no upstream commands.

The final native/API/paired results, exact APK identity and release packaging evidence are recorded in `tmp/ux-audit-2026-11-04/acceptance-results.json`. The directory retains RED/GREEN/full logs, screenshots, sidecar logs, the pre-audit source checkpoint and release/16KB audit. Its date reflects the audit's start; completion is November5. The append-only decision trail is `tmp/tv-redesign/decisions.tsv`.

Native lint reports zero errors, with48debug/47release nonblocking warnings, principally unused resources, style suggestions and API constants. The final native binary is unchanged after the playlist geometry fix. Sustained playback used the verified edition/outage fixes; the subsequent cleanup-only backend change was checked by the full API suite, injected failure tests and both final real stops. The receipt records both server bundle identities rather than attributing the earlier play-through to a later build.

Two test-harness assumptions were corrected without product changes: a partially clipped bottom playlist row must not be measured as a fully visible button, and the Google TV launcher needs to settle between force-stop and cold relaunch. Their original observations and lifecycle evidence are preserved. Final paired checks include explicit playlist D-pad movement; most other real-library smoke steps use pointer taps and Back. The device suite supplies the broader remote/focus regression coverage.

Status foreground/background contrast ratios are 9.54:1 success,10.41:1 pending,7.54:1 progress,7.69:1 attention and8.87:1 neutral. Labels remain explicit; color is supplementary. The focused status device test verifies that the success color survives the white row focus state.

A stricter saved-resume check initially failed after a short Start Over: playback reached36seconds but Plex returned its prior960974ms marker. Sanitized probes confirmed the actual position was reported correctly; neither changing the timeline verb nor a diagnostic saved-progress call made short playback persist. A longer run saved88611ms and returned that exact value on a fresh Plex metadata read, without the diagnostic write enabled. This establishes a short-playback behavior in this upstream setup, not a universal threshold. Final resume acceptance must use a meaningful play-through and assert both lower and upper bounds so an older offset cannot accidentally pass. No local progress override, watched toggle or server preference change was introduced. Transport follows the [official PMS timeline API](https://developer.plex.tv/pms/).

## Production boundary

No real requests, issues, ratings, watched toggles or playlist removals were submitted during acceptance. Their success/failure/permission/race cases are fixture-tested. Pairing secrets were not inspected or printed. Real acceptance uses the existing paired test sidecar on9002; the main audit's server/configuration is untouched.

Unsigned release packaging, shrinking, lint and16KB alignment are checked separately from emulator debug behavior. Production signing/distribution and physical-TV validation remain separate release requirements: hardware remotes/timing, overscan, HDR/audio passthrough, device performance and slow-network conditions need actual hardware. Emulator verification does not establish that every device or upstream configuration is production-ready.
