# Android TV Playback, Controls, and Branding Repair — November 4, 2026

The reproduced HLS startup failure is repaired. Native controls now use consistent sizing and spacing, the real Watchtower wordmark and Inter, and support both remote navigation and pointer clicks.

## Playback Root Cause

Plex negotiation sent the shared catalog client identifier in its HTTP header while its query and HLS startup used a fresh per-playback identifier. Plex accepted the decision but could reject startup with HTTP 400. A controlled experiment showed that explicitly adding offset=0 did not fix it; matching the decision header to the startup client identifier did. The shared Plex client now carries that matching identifier. Native timeline and final-stop reports also use the stream's own identifier.

The regression failed with expected unique-playback-client, received shared-catalog-client before the fix. Native timeline/stop tests exercise actual outgoing identity headers and preserve profile authentication, principal rechecks, and the default catalog identity.

## Uniform Controls and Real Pointer Support

- Symbol controls use fixed 48dp targets in 64×68dp cells, replacing the previous 80×102dp allocation and 56dp buttons. Focus no longer enlarges controls. Focus captions remain readable at 1.3× text.
- Value controls use minimum 48dp height, matching corners and fixed focus size. Browse/detail content uses a shared 32dp gutter; header and pagination rows align to their controls.
- The expanded and compact rail and pairing screen use the existing public/logo.png wordmark. Licensed Inter is bundled for all typography roles, including editable fields.
- TV Material's remote-oriented controls ignored actual taps. A shared pointer modifier now activates the existing callback once, observes disabled state, and focuses the clicked control for subsequent remote input. It covers symbol actions, navigation, cards and option controls.
- Clicking playing video reveals hidden controls. Controls remain disabled behind player menus, and closing a menu resets the controls timeout.

A real pointer pass opened a poster, started playback, revealed auto-hidden controls, paused/resumed, opened Audio, returned with hardware Back, and exited through More. The original pointer regression failed with expected 1, actual 0 before the repair. It now also checks disabled suppression and mixed-input focus.

## Emulator Navigation

The existing watchtower-tv-36-16k AVD had hw.keyboard=no. It is now enabled and was cold-booted; Android detects qwerty2. The SDK's own keyboard service successfully exercised ArrowDown, Enter and GoBack with focused-poster restoration. Temporary local authorization keys were removed after each check.

To navigate:

1. Click the emulator display to give its window keyboard focus.
2. Use arrow keys to move and Enter to select.
3. Use Back in the TV Remote panel or emulator toolbar to go up a level. Left from content enters the navigation rail.
4. Mouse clicks now work on posters, actions and player controls. Click the video to reveal hidden controls.
5. If macOS shortcuts intercept input, open Extended Controls → Settings → General → Send keyboard shortcuts to → Virtual device. The extended controls also contain Directional Pad / TV Remote.

These settings and controls are described in the [Android emulator documentation](https://developer.android.com/studio/run/emulator-extended-controls). The user confirmed that arrow keys and Enter navigate after this repair. The TV Remote panel was opened for immediate use; guest-service checks separately exercised Down, Enter and Back.
